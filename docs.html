ENTERPRISE ARCHITECTURE DECISION RECORDS (ADRS)

Architecture & Governance Records

High-level decision records governing CAIRN's enterprise trust plane, dual-sandbox runtimes, tiered execution assurance ladder, and content-based security boundaries.

ADR-0001 • ACCEPTED

Default-Deny Tool Gatekeeper

All automated tool invocations pass through a single, default-deny governance choke point. Policy evaluation occurs before execution, attributing actions to verified OS principals.

CHOKE_POINT: ToolRegistry.executeTool | Gate: Default-Deny
ADR-0002 • ACCEPTED

Pillar Contract Chain & Interchangeability

Defines strict contract schemas across execution states (INTENT → PLANNED → EXECUTING → EVIDENCE → VERIFYING → ACCEPTED), enabling hot-swappable local and cloud model providers.

CONTRACT_CHAIN: Strict Validation | Model Interchangeable
ADR-0003 • ACCEPTED

FORGE Synthesis & Code Verification Loop

Integrates pre-execution syntax validation and canary probes before code verification. Prevents unparseable or absent toolchains from masquerading as clean parse runs.

CANARY_PROBE: Active | Rubber-Stamp Prevention: Verified
ADR-0004 • ACCEPTED

Dynamic Hardware Assessment & Assessor

Automated probing of local GPU/CPU hardware capabilities to dynamic route tasks based on observed VRAM, compute throughput, and real-time TPS benchmarks.

HARDWARE_PROBE: Dynamic VRAM Sensing | Fleet Matching
ADR-0005 • ACCEPTED

Absolute Observability & Audit Provenance

Captures cryptographic SHA-256 decision ledgers correlated with telemetry logs, establishing tamper-evident decision lineage across every system turn.

AUDIT_LEDGER: SHA-256 Hash Chain | Trace correlation: Active
ADR-0006 • ACCEPTED

Honest Disclosure Over Absolute Claims

The philosophical spine of CAIRN: honest disclosure of unestablished properties over absolute claims. Never report a static check or un-executed script as runtime verification.

DISCLOSURE_PRINCIPLE: Truthful Caveats | Zero Over-Claims
ADR-0007 • ACCEPTED

CRUCIBLE Execution Pillar

Enforces disposable, isolated execution runtimes for synthesized code. Disables networking by default, applies read-only mounts, and bounds CPU and memory usage.

CRUCIBLE_SANDBOX: Isolated Runtime | Network: Disabled
ADR-0008 • ACCEPTED

Tiered Execution Assurance Ladder

Establishes explicit 6-rung verification tiers (unverified → static_only → sandbox_executed → behaviour_checked → deterministic → idempotent). Supports both Docker containers and Windows Sandbox VM escalation.

DUAL_SANDBOX: Docker + Windows Sandbox VM | Tiered Assurance
ADR-0009 • ACCEPTED

Outcome Assertion & Verification

Enforces proof-of-completion checks against explicitly defined contract criteria before transitioning a contract state to ACCEPTED. Prevents silent failure loops.

OUTCOME_ASSERTION: Intent Verification | Proof Required
ADR-0010 • ACCEPTED

Frontier Execution & Security Egress Gate

Content-based inspection layer evaluating all outgoing payloads. Blocks credentials (secret_like) unconditionally across all boundaries, gates cloud escalation, and meters token costs.

EGRESS_GATE: Secret Denial: Strict | Token Costing: Active
ADR-0011 • ACCEPTED

Website Brand & Content Governance

Establishes Palantir-class visual identity (Slate, Graphite, Limestone, Oxide Green), word count discipline, category vocabulary ownership, and proof-first proof mechanics.

BRAND_GOVERNANCE: Zero Neon Hype | Palantir-Class Restraint
ADR-0012 • ACCEPTED

Resolved Storage & Vault Path Isolation

Mandates a single, verified storage resolution mechanism (VAULT_DIR) across all subsystem modules, protecting host paths and ensuring environment isolation.

VAULT_ISOLATION: Resolved Standard Path | Path Masking: Enforced
