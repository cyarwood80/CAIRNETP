ENTERPRISE ARCHITECTURE DECISION RECORDS (ADRS)

Architecture & Governance Records

High-level architectural decision records governing CAIRN's enterprise trust plane, dual-sandbox runtimes, tiered execution assurance ladder, and content-based security boundaries.

ADR-0001 • ACCEPTED

Default-Deny Governance Gatekeeper

All automated tool invocations pass through a single, default-deny security boundary. Policy clearance occurs before execution, attributing actions strictly to verified principal roles.

GOVERNANCE_GATE: Unified Choke Point | Default-Deny
ADR-0002 • ACCEPTED

Pillar Contract Chain & Model Flexibility

Defines strict contract schemas across execution states, enabling hot-swappable local and cloud model backings without altering downstream governance boundaries.

CONTRACT_SCHEMA: Sealed Lifecycle | Model Interchangeable
ADR-0003 • ACCEPTED

Code Synthesis & Verification Loop

Integrates pre-execution syntax validation and automated toolchain canary probes. Prevents unparseable or absent toolchains from masquerading as clean execution runs.

CANARY_PROBE: Active | Environment Validation: Verified
ADR-0004 • ACCEPTED

Dynamic Compute Assessment & Router

Automated real-time probing of local GPU/CPU hardware capabilities to dynamically assign workload tasks based on observed compute capacity and throughput.

HARDWARE_PROBE: Dynamic VRAM Sensing | Capacity Allocation
ADR-0005 • ACCEPTED

Immutable Audit Provenance & Observability

Captures cryptographic SHA-256 decision ledgers correlated with operational telemetry logs, establishing verifiable decision lineage across every system turn.

AUDIT_PROVENANCE: SHA-256 Hash Chain | Trace Correlation
ADR-0006 • ACCEPTED

Honest Disclosure Over Absolute Claims

The philosophical spine of CAIRN: honest disclosure of unestablished properties over absolute claims. Never report a static check or un-executed script as runtime verification.

DISCLOSURE_PRINCIPLE: Truthful Caveats | Zero False Claims
ADR-0007 • ACCEPTED

Isolated Execution Containment

Enforces disposable, isolated execution runtimes for synthesized code. Disables networking by default, applies read-only mounts, and bounds CPU and memory usage.

CONTAINMENT_GATE: Isolated Runtime | Network: Disabled
ADR-0008 • ACCEPTED

Tiered Execution Assurance Framework

Establishes explicit 6-rung verification tiers (unverified → static_only → sandbox_executed → behaviour_checked → deterministic → idempotent). Supports both disposable containers and native virtual machine escalation.

TIERED_ASSURANCE: Dual-Runtime Sandbox | Explicit Verification
ADR-0009 • ACCEPTED

Outcome Assertion & Intent Verification

Enforces proof-of-completion checks against explicitly defined contract criteria before confirming task completion. Prevents unverified repair loops.

OUTCOME_ASSERTION: Intent Verification | Proof Required
ADR-0010 • ACCEPTED

Frontier Egress & Cost Governance

Content-based inspection layer evaluating outgoing payloads. Denies credentials automatically across all boundaries, gates cloud escalation, and meters token costs.

EGRESS_GATE: Secret Denial: Strict | Token Costing: Active
ADR-0012 • ACCEPTED

Isolated Storage Path Resolution

Mandates a single, verified storage resolution mechanism across all subsystem modules, protecting host paths and ensuring environment isolation.

STORAGE_ISOLATION: Resolved Path Standard | Path Masking
