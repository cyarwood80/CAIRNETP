The Seven Pillars of CAIRN

A deterministic, 7-stage execution pipeline enforcing schema contracts, hardware isolation, and cryptographic provenance from prompt ingress to verified telemetry.

PILLAR EXECUTION PIPELINE FLOW DETERMINISTIC SEQUENCE
PATH
→
Workflow Intelligence & Model Router Generates multi-step execution plans and routes workloads dynamically across local or cloud model backends.
CAIRN
→
Enterprise Trust & Security Gate Validates parameter schemas, strips prompt injection attempts, and enforces least-privilege approval clearance.
COMPASS
→
Governance Intelligence & Audit Provenance Evaluates organizational policy, least-privilege RBAC, and records cryptographically signed decision trails.
ATLAS
→
Knowledge Infrastructure & Graph Memory Retrieves verified institutional context, vector embeddings, and maintains persistent graph memory.
FORGE
→
Integration Platform & Code Generator Synthesizes sanitized tool code and dispatches workloads for hardware-isolated sandbox verification.
CRUCIBLE
→
Isolated Execution & Sandbox Engine Executes in ephemeral Linux Docker or Windows Sandbox Hyper-V VM, emitting verified state delta and assurance grade.
BEACON
→
Operational Awareness & Telemetry Surfaces final verified responses, audit disclosures, and streams real-time SIEM event feeds (Splunk, Datadog, Sentinel).

Enforcement Philosophy & Determinism Guarantee

  • BLOCKING Pillars (CAIRN, FORGE, CRUCIBLE): If a contract payload fails schema validation, execution is halted immediately (throwOnBlock = true). Unverified code or unvalidated execution results can never reach host storage or user context.
  • ADVISORY Pillars (PATH, BEACON, COMPASS, ATLAS): A contract defect does not stop execution, but surfaces a mandatory warning block in the response so the operator is informed of the defect.
THE 4-TIER CAIRN SYSTEM

The Cairn Architecture

The stacked cairn symbol represents the physical architecture: from user intent to cryptographic evidence.

Stone 1 (Top) • Ingress

1. Intent & Ingress Gate

Schema validation, AST parsing, and prompt injection filters before code touches any system.

Stone 2 • Governance

2. Policy & Governance Engine

Granular RBAC, egress IP whitelisting, and secret redaction enforced in microseconds.

Stone 3 • Execution

3. Dual-Runtime Sandbox

Dynamic hardware-isolated dispatch to Linux Docker or Windows Sandbox Hyper-V micro-VMs.

Stone 4 (Base) • Foundation

4. Cryptographic Evidence Ledger

Immutable SHA-256 decision records, SIEM audit streams, and EU AI Act compliance proofs.

Layered Trust Composition

Each layer builds deterministically upon the foundations below it. If any lower tier fails verification, execution halts immediately with zero side effects.
