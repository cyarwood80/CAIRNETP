The 7 Enterprise Pillars

CAIRN structures system capabilities into 7 formal architectural pillars to solve the "Privacy vs. Capability" tradeoff.

PILLAR 01 • SECURITY

1. CAIRN

Enterprise Trust & Default-Deny Security Gate. Evaluates all incoming prompt tool calls against strict default-deny policies before execution.

PILLAR 02 • ROUTER

2. PATH

Workflow Intelligence & Multi-Step Task Router. Classifies user intent, constructs execution plans, and routes tasks to the Model Fleet.

PILLAR 03 • TELEMETRY

3. BEACON

Operational Awareness & Real-Time Event Broadcast. Streams WebSocket status updates, session telemetry, and live execution progress.

PILLAR 04 • AUDIT

4. COMPASS

Governance Intelligence & Audit Provenance. Maintains immutable evidence logs for every session trace and pillar contract evaluation.

PILLAR 05 • KNOWLEDGE

5. ATLAS

Knowledge Infrastructure & Hybrid RAG. 4-layer memory combining Episodic SQLite Event Ledger, Knowledge Notes, Graphs, and Vector FTS.

PILLAR 06 • SYNTHESIS

6. FORGE

Integration Platform & Autonomous Code Engine. Executes 3-stage syntax parsing, pattern pre-filtering, and defect-repair code synthesis.

PILLAR 07 • SANDBOX

7. CRUCIBLE

Isolated Execution Engine & Sandbox Verification. Containerized Docker execution with zero network access, memory limits, and runtime traceback feedback.

Frontier Verification Cycle

How FORGE and CRUCIBLE ensure zero-defect, secure code execution before touching production hardware.

Stage 1: Static Parsing

Performs pre-flight syntax checks (`node -c`, `py_compile`, `PSParser`) on cryptographically isolated temp files before compilation.

Stage 2: Pattern Pre-Filtering

STRIX static pattern checks block malicious payloads, hardcoded secrets, arbitrary subprocess piping (`curl|bash`), and destructive filesystem commands.

Stage 3: Containerized Sandbox

Executes inside Docker (`--network none`, `--memory=128m`, `--read-only`). If runtime errors occur, CRUCIBLE feeds tracebacks back to FORGE for automatic repair.
